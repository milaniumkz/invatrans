# InvaTrans

Исходники Flutter-приложения пассажира/водителя (`inva_trans`) и административного приложения (`inva_trans_admin`). Firebase: Authentication, Firestore, Storage. Проверенная версия Flutter: **3.38.10**, Java 17; Android SDK 36 и NDK 28.2.13676358.

## Запуск

1. Установите Flutter 3.38.10, Java 17 и Android SDK. Выполните `flutter doctor`.
2. Получите конфигурацию приложения в Firebase Console проекта `invatrans-4d6e7`. Сохраните Android `google-services.json` в `<приложение>/android/app/`, iOS `GoogleService-Info.plist` в `<приложение>/ios/Runner/`. Используйте соответствующую регистрацию приложения.
3. В каталоге выбранного приложения выполните `flutter pub get`, затем `flutter run`.

Вход клиента работает через Firebase Phone Authentication. В Firebase должны быть включены Phone provider, SMS для нужной страны и сертификаты SHA-1/SHA-256 подписывающего ключа. Токены выдаёт Firebase; старый сервис `/create-token` закрыт для анонимных вызовов.

## Облачная сборка

GitHub → Actions → **Android release** → Run workflow. Выполняются тесты клиента и сборка подписанного release APK. APK доступен в Artifacts успешного запуска (требуется вход в GitHub). Подпись берётся из защищённых repository secrets:

| Secret | Значение |
|---|---|
| ANDROID_KEYSTORE_BASE64 | Base64 ключа JKS |
| ANDROID_KEY_ALIAS | Alias ключа |
| ANDROID_KEY_PASSWORD | Пароль ключа |
| ANDROID_STORE_PASSWORD | Пароль хранилища |
| GOOGLE_SERVICES_JSON_BASE64 | Base64 Android-конфигурации клиента |

Существующий тестовый ключ позволяет обновлять ранее выданный APK без удаления приложения. Сохраните отдельную резервную копию ключа. Не заменяйте его случайным ключом при каждой сборке.

## Управление сервером

Данные, аккаунты, SMS, индексы и правила доступны владельцу через [Firebase Console](https://console.firebase.google.com/project/invatrans-4d6e7/overview). GitHub хранит исходники и собирает приложение; доступ к репозиторию сам по себе не даёт доступа к Firebase. Для нового разработчика выдавайте отдельные роли Google Cloud/Firebase, а не общий ключ владельца.

В каталогах `firebase` находятся экспортированные функции, правила и индексы. **Правила из архива отличаются от опубликованных.** Автоматическое развёртывание сервера намеренно не настроено: сначала согласуйте ограничения доступа и проверьте их на эмуляторах. Не запускайте общий `firebase deploy` поверх рабочего проекта вслепую. Исходник закрытого старого сервиса выдачи токенов не входит в исходный архив.

## Проверки и ограничения

Клиент: `cd inva_trans && flutter test`. Проверено 10 тестов, реальный SMS-вход, сохранение существующего профиля и release APK 1.0.3 (4). Административное приложение включено как исходный экспорт, его полная работоспособность не подтверждена.

Рабочие каталоги меню/категорий/услуг пусты. Опубликованные правила Firestore слишком открыты и требуют исправления перед полноценной эксплуатацией. Полный цикл поездки на двух устройствах и уведомления ещё не проверены.

Пользовательские данные, резервные копии Auth, пароли, ключи подписи и архивы не публикуются. Настройки Firebase внутри клиентского Dart-кода являются публичной конфигурацией приложения, а не ключом администратора. Защита данных должна обеспечиваться серверными правилами.
